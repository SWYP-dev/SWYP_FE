# QA 리스트

최종 갱신일: 2026-10-07 (QA-005~QA-018 등록)

## 사용법

- **처리 순서**: 우선순위 **상 → 중 → 하** 순으로 처리한다.
- **상태**: `대기` / `진행중` / `완료` 3단계로 관리한다.
- **처리 워크플로우**: 항목별 실제 작업 절차(QA 진행 → 검증)는 [`.claude/rules/qa-rules.md`](../../.claude/rules/qa-rules.md)를 따른다.
- **참고 이미지**: 항목에 첨부할 이미지는 `docs/qa/images/` 아래에 `QA-001-1.png`처럼 항목 ID를 붙인 파일명으로 저장하고, 항목의 "참고 이미지" 필드에 상대경로로 기록한다.
- **태그**: 항목별 `태그` 필드로 기능 영역을 구분한다. 현재 사용 중인 태그는 아래와 같다.

| 태그 | 대상 기능 | 해당 항목 |
| --- | --- | --- |
| `#통합공고탐색` | 통합 공고 탐색 (검색/필터/페이지네이션) | QA-001 ~ QA-004 |
| `#지원현황관리` | 지원 현황 관리 (칸반 보드/지원 단계/드로어/마감일) | QA-005 ~ QA-010 |
| `#마감일정관리` | 마감 일정 관리 (알림/마감일 표시) | QA-011 ~ QA-013 |
| `#서류첨부` | 서류 첨부 (URL 카테고리/공고 링크) | QA-014 ~ QA-015 |
| `#기타` | 기타 (로그인 모달/메타데이터/메뉴명 등 공통) | QA-016 ~ QA-018 |

- **메시지 문구**: 토스트/에러 메시지 문구 기준은 [`TOAST_MESSAGES.md`](TOAST_MESSAGES.md)를 따른다.

#### [QA-006] 전형 단계 추가 중 입력 취소 UX 개선

- 기능명: 지원 현황 단계
- 태그: `#지원현황관리`
- 우선순위: 상
- 상태: 대기
- QA 내용: 신규 전형 단계 추가 도중 작성을 즉시 취소할 방법이 없음
- 상세 내용:
  - AS-IS:
    - 신규 전형 단계를 추가하는 도중 작성을 취소하고 싶을 때, 즉시 취소할 수 있는 방법(버튼 등)이 없다.
    - 이로 인해 사용자는 임의의 텍스트를 입력해 컬럼 생성을 완료한 뒤, 다시 해당 컬럼을 삭제해야 하는 불필요한 조작을 해야 한다.
  - TO-BE: 전형 단계 이름 입력란이 활성화된 상태에서 텍스트 입력 없이 컬럼 외부 영역을 클릭(Focus-out)하면, 생성 중이던 칸반 컬럼이 자동으로 취소(제거)되도록 개선한다.
- 참고 이미지: [images/QA-006-1.png](images/QA-006-1.png)(AS-IS 입력란 활성화 상태), [images/QA-006-2.png](images/QA-006-2.png)(AS-IS 빈 값 에러 상태)
- 비고: 작성자 손진영. 텍스트를 입력한 상태에서 focus-out 시의 동작(생성 확정 vs 유지)은 명시되지 않음 → 확인 필요.

- 기능명: 지원 현황 카드

- 상세 내용:
  - AS-IS: `지원 전` 단계에서 공고 카드에 지원 마감일까지 남은 기한을 알려주는 D-Day 뱃지 UI 요소가 존재하지 않아 마감일까지 남은 일수에 대한 직관적인 파악이 어렵다.

    - 다른 단계로 이동하면 뱃지를 비노출(삭제) 처리한다. (마감 여부 상관 없음)

- 비고: 작성자 이세은, 담당자 SonSeyoung(백엔드). 프론트 수정이 필요한 부분이 있으면 프론트에서도 작업 가능. 뱃지 디자인(색상/사이즈)은 Figma 스펙 확인 필요. 마감일이 없는 공고(상시 채용 등)의 뱃지 처리 방식은 미정 → PM/디자인 확인 필요.

#### [QA-003] 페이지네이션 UI/UX 개선 (5단위 → 10단위 블록)

- 기능명: 통합 공고 탐색
- 태그: `#통합공고탐색`
- 우선순위: 중
- 상태: 대기
- QA 내용: 페이지네이션이 5페이지 단위 슬라이딩 방식이라 먼 페이지 이동 시 클릭 횟수가 과도함
- 상세 내용:
  - AS-IS: 현재 페이지네이션은 선택한 페이지를 중심으로 앞뒤 2페이지씩만 노출되는 '5페이지 단위 슬라이딩 방식'으로 구현되어 있다. 전체 데이터가 많을 경우 마지막 페이지나 먼 페이지로 이동하기 위한 클릭 횟수가 과도하게 늘어나 탐색 효율성이 떨어진다.
  - TO-BE: 화살표 버튼의 기능은 유지하되, 한 화면에 노출되는 페이지 단위를 5개에서 10개 블록(Chunk) 단위로 확장한다. 이전/다음 화살표를 누르면 1페이지씩 밀리는 것이 아니라 '1~10', '11~20'과 같이 10개 단위로 한 번에 건너뛸 수 있도록 변경한다.

#### [QA-011] 알림창 진입 시 새 알림 빨간 점 제거

- 기능명: 마감 일정 관리
- 태그: `#마감일정관리`
- 우선순위: 중
- 상태: 대기
- QA 내용: 새 알림 확인 후 알림창을 나와도 빨간 점이 사라지지 않음
- 상세 내용:
  - AS-IS:
    - 새 알림에 대한 빨간 점이 떠서 알림창에 들어가 확인하고 나와도 빨간 점이 그대로 있다.
    - 빨간 점을 지우려면 불필요하게 개별 알림 항목을 일일이 클릭해서 삭제하는 방법밖에 없다.
  - TO-BE: 유저가 알림 아이콘을 클릭하여 알림창을 오픈하는 시점에 신규 알림 노티(빨간 점)가 사라져야 한다.
- 참고 이미지: -
- 비고: 백엔드 읽음 처리(알림 읽음 API/상태 반영) 여부 확인 필요. API 명세서 확인 후 백엔드(세영님/동섭님)와 협의.

#### [QA-017] 페이지별 메타 타이틀 추가 (예: 취합 | 지원 현황)

- 기능명: 페이지 메타데이터
- 태그: `#기타`
- 우선순위: 중
- 상태: 대기
- QA 내용: 브라우저 탭 이름이 '취합'으로만 고정되어 있어 페이지 구분이 어려움
- 상세 내용:
  - AS-IS:
    - 현재 서비스 내 브라우저 탭에 표시되는 이름이 '취합'으로만 고정되어 있다.
    - 타 서비스들처럼 페이지 목적이 명확히 보이지 않아, 사용자가 여러 탭을 띄워놓고 작업할 때 어떤 탭이 우리 서비스인지 직관적으로 찾기 불편하다.
  - TO-BE: 사용자가 현재 어떤 페이지를 보고 있는지 알 수 있도록 페이지별로 탭 이름(메타 타이틀)을 상세하게 변경한다.
    - 적용 규칙:
      - 로그인: `취합 | 로그인`
      - 채용 공고: `취합 | 채용 공고`
      - 스크랩: `취합 | 스크랩`
      - 지원 현황: `취합 | 지원 현황`
      - 지원 마감일: `취합 | 지원 마감일`
      - 계정 및 서비스 설정: `취합 | 계정 및 설정`
