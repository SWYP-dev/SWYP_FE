## 사용법

- **처리 순서**: 우선순위 **상 → 중 → 하** 순으로 처리한다.
- **상태**: `대기` / `진행중` / `완료` 3단계로 관리한다.
- **처리 워크플로우**: 항목별 실제 작업 절차(QA 진행 → 검증)는 [`.claude/rules/qa-rules.md`](../../.claude/rules/qa-rules.md)를 따른다.
- **참고 이미지**: 항목에 첨부할 이미지는 `docs/qa/images/` 아래에 `QA-001-1.png`처럼 항목 ID를 붙인 파일명으로 저장하고, 항목의 "참고 이미지" 필드에 상대경로로 기록한다.
- **태그**: 항목별 `태그` 필드로 기능 영역을 구분한다. 현재 사용 중인 태그는 아래와 같다.

| 태그 | 대상 기능 | 해당 항목 |
| --- | --- | --- |
| `#통합공고탐색` | 통합 공고 탐색 (검색/필터/페이지네이션/공고 카드 표시) | QA-001 ~ QA-004, QA-019 ~ QA-020 |
| `#지원현황관리` | 지원 현황 관리 (칸반 보드/지원 단계/드로어/마감일) | QA-005 ~ QA-010 |
| `#마감일정관리` | 마감 일정 관리 (알림/마감일 표시) | QA-011 ~ QA-013 |
| `#서류첨부` | 서류 첨부 (URL 카테고리/공고 링크) | QA-014 ~ QA-015 |
| `#기타` | 기타 (로그인 모달/메타데이터/메뉴명/계정·알림 설정 등 공통) | QA-016 ~ QA-018, QA-021 |

- **메시지 문구**: 토스트/에러 메시지 문구 기준은 [`TOAST_MESSAGES.md`](TOAST_MESSAGES.md)를 따른다.

- 상태: 완료

#### [QA-021] 알림 채널(이메일/카카오톡)별 수신 여부 설정

- 태그: `#기타`
- 우선순위: 상

- QA 내용: 각 알림 채널(이메일/카카오톡)의 수신 여부를 유저가 능동적으로 관리할 수 있어야 함
- 상세 내용:
  - AS-IS:
    - 원치 않는 채용 공고 일정이 지속적으로 발송될 경우 유저가 피로감을 느껴 서비스 자체의 이탈율이 증가할 수 있다.
    - 유저 개개인의 선호 수신 채널(카카오톡 알림만 수신, 이메일도 함께 수신 등)을 반영할 수 없어 개인화된 알림을 제공하지 못한다.

    - 이메일 알림: 스위치를 켜거나 끄면 누르는 즉시 변경 내용 저장. OFF로 끌 때 모든 이메일 알림 제공 X, ON으로 켤 때 모든 이메일 알림 제공 O.
    - 카카오톡 알림: 스위치를 켜거나 끄면 누르는 즉시 변경 내용 저장. OFF로 끌 때 모든 카카오톡 알림 제공 X, ON으로 켤 때 모든 카카오톡 알림 제공 O.
    - (같은 기획 문서의 계정 관리 항목) 프로필 닉네임 유효성 실패 시 "2~10자의 한글, 영문, 숫자만 사용 가능해요.", 이메일 정보 수정 불가, 회원 탈퇴 클릭 시 재확인 모달("계정과 모든 활동 기록이 삭제돼요.") 후 최종 탈퇴 시 계정 삭제 처리 및 로그인 화면 이동.
- 참고 이미지: [images/QA-021-1.png](images/QA-021-1.png)(PRD 6. 계정 및 서비스 설정 — 6.2 알림 수신), [images/QA-021-2.png](images/QA-021-2.png)(Swagger 5.2 알림 설정 수정 API)
- 비고: **백엔드 진행 상황(2026-10-15)**: 이메일 토글(5.2 `PATCH /api/v1/notifications/settings`, `emailEnabled`)은 구현 완료. 카카오 알림톡 리마인드는 사업자 등록증이 필요해 일단 보류(패스).

  **프론트 진행·기획 확정(2026-10-15)**: 이메일 토글은 누르는 즉시 5.2로 저장(연동 완료). 서버 저장값을 그대로 쓰고 저장 요청 중에는 누른 값을 먼저 보여주도록 바꿔, 저장에 실패하면 스위치가 변경 전 값으로 자동 복귀함(기존 로컬 state 동기화 방식과 set-state-in-effect eslint 에러도 함께 제거). 기획 확정: ① 저장 성공/실패 시 안내 문구(토스트) 불필요 ② 카카오톡 토글은 현재 구현 그대로 비활성 유지(백엔드 알림톡 보류 — 사업자 등록증 필요, API 추가 시 5.1/5.2 필드 반영 후 토글 활성화·연동) ③ 설정 메뉴명은 '알림'으로 통일(현 구현 유지) ④ 계정 관리 문구("2~10자의 한글, 영문, 숫자만 사용 가능해요.", "계정과 모든 활동 기록이 삭제돼요.")는 확정본이며 현재 구현(`ProfileEditModal`, `DeleteAccountModal`)과 일치함을 확인. **완료 처리(2026-10-15)**: 카카오톡 알림은 백엔드 보류(사업자 등록증 필요)로 이번 범위에서 제외(카카오 알림톡 API가 추가되면 별도 항목으로 5.1/5.2 필드 반영 및 토글 연동). 이메일 OFF 시 실제 발송 중단 여부(발송 측 `emailEnabled` 확인)는 백엔드에서 처리·확인하므로 프론트 작업 없음.
