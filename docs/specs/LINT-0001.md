# LINT-0001 — develop의 기존 lint 오류 7건 정리 (동작 변경 없음)

## 배경

- `npm run lint`가 develop에서 오류 7건(경고 0건)으로 실패한다. 그래서 CI의 `lint` 잡은 `continue-on-error`로 현황만 표시하고, PR Validation 체크가 항상 X로 보인다 (`docs/workflow/claude-codex-plan.md` 15장 lint 필수화 행)
- 오류 목록 (2026-10-22 develop `657f057` 기준)

| 파일                                                          | 줄            | 규칙                              | 원인                                                                                                                                            |
| ------------------------------------------------------------- | ------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/jobs/page.tsx`                                       | 78            | `react-hooks/set-state-in-effect` | `useEffect` 안에서 `setJobPostingIdMap`을 동기 호출 (피드 응답의 `jobPostingId`를 맵에 누적)                                                    |
| `src/features/deadlines/components/DeadlineList.tsx`          | 56            | `react-hooks/set-state-in-effect` | `useEffect` 안에서 `setViewingCardId`를 동기 호출 (`?cardId=` 딥링크를 데이터 로드 후 1회 적용)                                                 |
| `src/features/deadlines/components/EditDeadlineCardModal.tsx` | 199~210 (5건) | `react-hooks/refs`                | `usePopoverTrigger()` 반환 객체를 `stageDropdown`으로 통째로 받아 렌더 중 `stageDropdown.xxx`로 접근 (객체 안에 ref가 있어 전체가 ref로 취급됨) |

- 같은 훅을 쓰는 다른 컴포넌트(`ProfileMenu.tsx`, `NotificationBell.tsx`, `AttachmentCategoryDropdown.tsx`, `KanbanColumn.tsx` 등)는 반환값을 구조 분해해서 쓰고 있어 오류가 없다
- 이 명세를 쓰면서 아래 설계 결정대로 워크트리에서 시험 적용해 `npm run lint` 0건(오류·경고), `npm run typecheck`·`npm run build` 통과를 확인했다

## 범위

**포함**

- 위 3개 파일의 lint 오류 7건을 코드 수정으로 없앤다. 화면 동작은 바꾸지 않는다
- 수정으로 쓰지 않게 된 import(`useEffect`) 제거

**제외**

- lint 필수화(`ci.yml`의 `continue-on-error` 제거, `scripts/ai/spec-file.mjs`의 `CI_COMMANDS`에 lint 추가, 명세 템플릿·`AGENTS.md`·`CLAUDE.md` 문구 정리). 정책 경로라 이 구현 PR에서 바꿀 수 없으므로 머지 후 일반 브랜치 PR로 처리
- 위 3개 파일 밖의 리팩토링, 같은 파일 안의 다른 코드 정리
- `src/components/ui/popover.tsx`(`usePopoverTrigger`·`Popover`) 수정

## 설계 결정

- **lint 규칙을 끄거나 우회하지 않는다.** `eslint-disable` 주석, `eslint.config.mjs` 수정은 하지 않는다
- `src/app/jobs/page.tsx`: `useEffect`를 없애고, React 문서의 "이전 렌더의 값을 state로 저장해 렌더 중에 비교하는" 패턴으로 바꾼다
  - `const [syncedData, setSyncedData] = useState<typeof data>(undefined);` — 초기값은 반드시 `undefined`. `useState(data)`로 두면 React Query 캐시에 데이터가 이미 있을 때 첫 렌더에서 맵이 채워지지 않아 기존 동작과 달라진다
  - 렌더 중 `if (data !== syncedData) { setSyncedData(data); if (data) setJobPostingIdMap((prev) => ...) }`
  - `setJobPostingIdMap`의 갱신 함수 내용(이전 맵 복사 후 `item.jobPostingId != null`인 항목만 `next[item.id]`에 덮어쓰기)은 지금 그대로 둔다. 맵은 페이지가 바뀌어도 누적된다
- `src/features/deadlines/components/DeadlineList.tsx`: `useEffect`를 없애고 같은 조건을 렌더 중에 검사한다
  - `if (!hasAppliedCardIdParam && data) { ...지금과 같은 cardId 검사·setViewingCardId... ; setHasAppliedCardIdParam(true); }`
  - `hasAppliedCardIdParam` 가드로 데이터 로드 후 1회만 적용되는 동작은 그대로다
- `src/features/deadlines/components/EditDeadlineCardModal.tsx`: 다른 컴포넌트처럼 `usePopoverTrigger()` 반환값을 구조 분해한다
  - `const { isOpen: isStageOpen, triggerRef: stageTriggerRef, toggle: toggleStage, close: closeStage } = usePopoverTrigger<HTMLButtonElement>();`
  - JSX와 `onSelect`의 `stageDropdown.xxx`를 위 이름으로 바꾼다. 마크업·클래스는 바꾸지 않는다
- 바꾼 부분에는 왜 effect를 쓰지 않는지 한국어 주석을 짧게 남긴다 (`.claude/rules/code-style.md` 주석 규칙)
- BE 의존: 없음

## 수용 기준

- AC-01 `src/app/jobs/page.tsx`에 `useEffect`가 없고, 피드 데이터(`data`)가 바뀔 때마다(첫 로드 포함, 캐시된 데이터로 처음 렌더되는 경우 포함) 렌더 중 비교로 `jobPostingIdMap`에 `jobPostingId`가 누적된다. 갱신 함수의 내용은 기존과 같다
- AC-02 `src/features/deadlines/components/DeadlineList.tsx`에 `useEffect`가 없고, `?cardId=` 딥링크는 데이터 로드 후 렌더 중에 1회만 적용된다 (`hasAppliedCardIdParam` 가드 유지, 해당 카드가 있을 때만 `setViewingCardId`)
- AC-03 `src/features/deadlines/components/EditDeadlineCardModal.tsx`가 `usePopoverTrigger()` 반환값을 구조 분해해 쓰고, `stageDropdown` 식별자가 남아 있지 않다. 전형 단계 드롭다운의 마크업·클래스는 그대로다
- AC-04 `eslint-disable` 주석이 추가되지 않고 `eslint.config.mjs`가 바뀌지 않는다. 변경 파일은 위 3개뿐이다
- AC-05 `npm run typecheck`·`npm run build`가 통과한다
- AC-06 [manual] 구현 PR의 `ci / lint (현황 표시)` 체크가 통과(초록)로 표시된다
- AC-07 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`에서 로그인 후 아래 동작이 기존과 같다
  - `/jobs`: 공고 스크랩 → 스크랩 해제가 오류 토스트 없이 된다 (해제는 `jobPostingIdMap`을 쓴다)
  - `/deadlines?cardId=<마감일 목록에 있는 카드 ID>`로 들어가면 그 카드의 상세 Drawer가 열린다
  - `/deadlines`에서 카드 수정 모달을 열고 "전형 단계" 드롭다운을 열기·선택·닫기 할 수 있고, 저장하면 단계가 바뀐다
