# HT-004 — 전형 단계 추가 중 형식 오류 상태에서도 언제든 취소할 수 있게 개선

## 배경

- 사용성 개선 리스트 `docs/heightening/Heightening_LIST.md`의 HT-004 항목이다. 단계를 실수로 추가했거나 이름을 잘못 쓴 경우 바로 취소할 수 없어, 아무 이름이나 넣어 만든 뒤 삭제하는 우회 행동이 생긴다 (AS-IS `docs/heightening/images/HT-004-1.png`)
- TO-BE
  - Enter: 이름이 유효하면 저장
  - ESC: 입력 취소, 단계 자체가 사라짐
  - 바깥 클릭: 이름이 있으면 저장, 비어 있으면 그냥 사라짐
  - 이름이 형식에 맞지 않을 때: 에러 문구는 보여주되, 취소는 언제든 가능해야 함
- 지금 코드 (2026-10-22 develop `6c9fc40` 기준, `src/features/kanban/components/KanbanColumn.tsx`의 draft 컬럼)
  - Enter → `commit()`: `validateStageName` 통과 시 `onConfirmDraft`, 실패 시 에러 문구 표시. **TO-BE와 같다**
  - ESC → `cancel()` → `onCancelDraft`(draft 제거). **TO-BE와 같다**. 단, 입력란에 포커스가 있을 때만 동작한다
  - 바깥 클릭(`handleBlur`): 비어 있으면 `onCancelDraft`, 이름이 있으면 `commit()` (QA-006, PR #178). **TO-BE와 같다**
  - **남은 문제**: 이름이 형식에 맞지 않는 상태(예: 1글자, 낱자음만)에서 바깥을 클릭하면 에러 문구와 함께 draft 컬럼이 남고 입력란 포커스가 빠진다. 이때 ESC는 동작하지 않고, 헤더의 `+`·더보기(···) 버튼은 draft에서 `disabled`라 취소할 수단이 없다. 입력란을 다시 클릭해 ESC를 누르거나 글자를 모두 지우고 바깥을 클릭해야 한다
  - 서버가 이름 오류(K006 중복 등)를 돌려준 경우에도 `KanbanBoard.tsx`의 `handleConfirmDraft`가 draft를 남겨 두므로 같은 상황이 된다

## 범위

**포함**

- draft 컬럼 헤더에 "단계 추가 취소" 닫기(X) 버튼을 두어, 에러 상태·포커스 여부와 상관없이 한 번에 draft를 취소할 수 있게 한다
- 닫기 버튼을 누르는 동작이 입력란 blur → 저장(`commit`)을 먼저 일으키지 않게 한다
- ESC로 취소할 때 이어지는 blur가 저장을 일으키지 않게 한다

**제외**

- Enter·바깥 클릭·빈 값 취소 등 이미 TO-BE와 같은 동작, 이름 검증 규칙(`validateStageName`)과 에러 문구는 바꾸지 않는다
- 기존 단계의 이름 수정(draft가 아닌 컬럼의 편집 모드)은 바꾸지 않는다
- 서버 이름 오류를 토스트로 알리는 방식(`handleConfirmDraft`)은 바꾸지 않는다
- `docs/heightening/Heightening_LIST.md`의 상태 갱신은 구현 PR에서 하지 않는다 (머지 후 일반 브랜치에서 처리)

## 설계 결정

- 디자인 시안이 없으므로, 헤더 오른쪽 아이콘 버튼과 같은 형태로 만든다. 새 아이콘을 만들지 않고 `src/components/ui/icons.tsx`의 `CloseIcon`을 쓴다
- `src/features/kanban/components/KanbanColumn.tsx`
  - draft(`isDraft`)일 때 헤더 오른쪽 버튼 영역에는 지금의 비활성 `+`·더보기(···) 버튼과 Popover 대신 닫기 버튼 하나만 렌더링한다. draft가 아닐 때의 헤더는 그대로 둔다
  - 닫기 버튼: `type="button"`, `aria-label="단계 추가 취소"`, 클래스 `flex size-5 items-center justify-center text-icon-gray`, 내용 `<CloseIcon size={20} />`
  - 닫기 버튼의 `onMouseDown`에서 `e.preventDefault()`를 호출해 입력란 포커스가 빠지지 않게 한다. 포커스가 빠지면 `handleBlur`가 유효한 이름을 먼저 저장해 버리기 때문이다
  - 닫기 버튼의 `onClick`은 `onCancelDraft?.()`를 호출한다
  - 취소 뒤 blur로 저장되는 것을 막기 위해 `useRef(false)`로 취소 여부를 기록한다. `cancel()`의 draft 분기와 닫기 버튼 `onClick`에서 `true`로 바꾸고, `handleBlur`는 맨 앞에서 이 값이 `true`면 아무것도 하지 않고 return한다. ref는 렌더 중에 읽지 않는다 (`react-hooks/refs` lint 규칙)
- 바꾼 부분에는 왜 바꿨는지 한국어 주석을 짧게 남긴다 (`.claude/rules/code-style.md`)
- BE 의존: 없음

## 수용 기준

- AC-01 `KanbanColumn.tsx`에서 `isDraft`일 때 헤더 오른쪽에 `aria-label="단계 추가 취소"`인 닫기 버튼(`CloseIcon`)만 렌더링되고, `+`·더보기 버튼은 렌더링되지 않는다. draft가 아닐 때 헤더의 `+`·더보기 버튼과 Popover는 기존과 같다
- AC-02 닫기 버튼은 `onMouseDown`에서 `preventDefault()`를 호출하고, `onClick`에서 `onCancelDraft`를 호출한다
- AC-03 `handleBlur`는 취소 여부 ref가 `true`면 `commit()`·`onCancelDraft`를 호출하지 않고 return한다. 이 ref는 `cancel()`의 draft 분기와 닫기 버튼 `onClick`에서 `true`가 되고, 렌더 중에 읽히지 않는다
- AC-04 `validateStageName`, Enter·ESC 키 처리 조건, 빈 값일 때 `handleBlur`의 취소 분기는 바뀌지 않는다. 변경 파일은 `KanbanColumn.tsx` 하나뿐이다
- AC-05 `npm run typecheck`·`npm run build`·`npm run lint`가 통과한다
- AC-06 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`의 `/kanban`에서 로그인 후 '전형 단계 추가'로 draft 컬럼을 연 상태에서 아래가 모두 맞다
  - 유효한 이름 입력 후 Enter → 단계가 생성된다
  - 이름을 입력한 채 ESC → draft가 사라지고 단계가 생성되지 않는다 (성공 토스트가 뜨지 않는다)
  - 빈 값으로 바깥 클릭 → draft가 사라진다 / 유효한 이름으로 바깥 클릭 → 단계가 생성된다
  - 1글자(예: "가")를 입력하고 바깥 클릭 → 에러 문구가 보이고, 그 상태에서 닫기(X) 버튼 한 번으로 draft가 사라진다
  - 유효한 이름을 입력한 상태에서 닫기(X) 버튼 → draft가 사라지고 단계가 생성되지 않는다
  - 기존 단계 헤더의 `+`·더보기(···) 메뉴는 기존과 같다
