# HT-003 — 기본 전형 단계 중 '면접'·'최종 결과'의 이름 수정·삭제 허용

## 배경

- 사용성 개선 리스트 `docs/heightening/Heightening_LIST.md`의 HT-003 항목이다. 기본 전형 단계의 이름 수정·삭제가 막혀 있어, 기업마다 다른 실제 전형 구성을 기본 단계에 반영할 수 없다 (AS-IS `docs/heightening/images/HT-003-1.png`)
  - 리스트 본문의 "지원 완료"는 실제 세 번째 기본 단계명인 "최종 결과"를 잘못 적은 것이다 (`src/features/kanban/utils/stageAnalytics.ts`의 `DEFAULT_STAGE_NAMES`)
- 확정된 정책 (PM 답변, 2026-10-25)

  | 전형 단계        | 이름 수정 | 삭제 | 순서 변경 |
  | ---------------- | --------- | ---- | --------- |
  | 지원 전          | 불가      | 불가 | 불가      |
  | 면접             | 가능      | 가능 | 가능      |
  | 최종 결과        | 가능      | 가능 | 가능      |
  | 사용자 추가 단계 | 가능      | 가능 | 가능      |

- 백엔드 답변 (2026-10-25): 기본 3단계 중 '지원 전'만 이름 변경(K023 `DEFAULT_STAGE_NAME_CHANGE_NOT_ALLOWED`)과 삭제(K004 `DEFAULT_STAGE_DELETE_NOT_ALLOWED`)를 제한한다. '지원 전'은 지원 마감 알림 대상 판단에 쓰이기 때문이다. '면접'·'최종 결과'는 이름 변경·삭제가 가능하다. 즉 FE만 바꾸면 되고 API 계약 변경은 없다
- 지금 코드 (2026-10-25 develop `dc4e4db` 기준)
  - `src/features/kanban/components/KanbanColumn.tsx`의 `isLocked = getStageType(stage) === 'default'`가 '지원 전'·'면접'·'최종 결과' 세 단계 모두를 잠근다. `getStageType`은 `isDefault`이거나 이름이 `DEFAULT_STAGE_NAMES`에 있으면 `'default'`를 돌려준다
  - `isLocked`이면 케밥 메뉴의 '이름 수정'·'삭제' 항목이 `disabled`이고, `startEditing`(메뉴·더블클릭 진입)이 바로 return하며, 단계명에 `cursor-text`가 붙지 않는다
  - 순서 변경은 이미 정책과 같다: 컬럼 드래그는 `useSortable`의 `disabled: isDraft || stage.name === '지원 전'`으로 '지원 전'만 막혀 있고, `KanbanBoard.tsx`의 단계 이동 처리도 '지원 전' 이름 기준으로 고정한다
  - 이름 수정·삭제 처리(`KanbanBoard.tsx`의 `onRenameStage`·`onDeleteStage` → `DeleteStageModal`)는 단계 종류와 상관없이 같은 흐름이라 그대로 쓸 수 있다
  - 파일 상단 주석(20~24행)이 "기획 확정(2026-07-26)에 따라 3개 기본 스테이지 모두 FE에서 이름 변경·삭제를 비활성화"라고 적고 있어 정책 변경에 맞지 않게 된다

## 범위

**포함**

- `KanbanColumn.tsx`의 이름 수정·삭제 잠금 기준을 '지원 전' 하나로 좁힌다
- 정책이 바뀐 이유가 드러나도록 파일 상단 주석을 고친다

**제외**

- 순서 변경(컬럼 드래그·`KanbanBoard.tsx`의 단계 이동 처리): 이미 정책과 같으므로 바꾸지 않는다
- 분석 이벤트의 단계 분류(`stageAnalytics.ts`의 `getStageType`·`getStageAnalyticsName`, `DEFAULT_STAGE_NAMES`)는 바꾸지 않는다. 이벤트 속성의 의미를 유지하기 위함이다
- `KanbanBoard.tsx`의 이름 수정 실패 처리(K023 토스트 포함)와 삭제 모달·되돌리기 흐름은 바꾸지 않는다
- 백엔드 API·`docs/API_SPEC.md`는 바꾸지 않는다
- `docs/heightening/Heightening_LIST.md`의 상태·"지원 완료" 오기 수정은 구현 PR에서 하지 않는다 (머지 후 일반 브랜치에서 처리)

## 설계 결정

- 잠금 기준은 `stage.name === '지원 전'`으로 한다. 같은 파일의 컬럼 드래그 비활성 조건과 `KanbanBoard.tsx`의 단계 고정 로직이 이미 이 이름 기준을 쓰므로 기준을 하나로 맞춘다. `isDefault`는 기준으로 쓰지 않는다 (서버가 기본 3단계에 내려주는 값이 정책과 일치한다고 확인되지 않았다)
- `src/features/kanban/components/KanbanColumn.tsx`
  - `const isLocked = stage.name === '지원 전';`으로 바꾼다. `isLocked`를 쓰는 곳(`startEditing`의 return 조건, 단계명 `cursor-text` 조건, 케밥 메뉴 두 항목의 `disabled`)은 그대로 이 값을 쓴다
  - 이로써 `getStageType`을 이 파일에서 더 쓰지 않게 되면 import를 지운다
  - 파일 상단 주석(20~24행)을 "'지원 전'은 지원 마감 알림 대상 판단에 쓰여 백엔드도 이름 변경(K023)·삭제(K004)를 막으므로 FE도 잠그고, '면접'·'최종 결과'는 HT-003 정책(2026-10-25)에 따라 사용자 추가 단계와 같이 이름 수정·삭제를 허용한다"는 취지의 한국어 주석으로 바꾼다
  - 케밥 메뉴 위 주석(QA-007)의 "기본 3개 단계(isLocked)"를 "'지원 전'(isLocked)"으로 고친다
- BE 의존: 없음

## 수용 기준

- AC-01 `KanbanColumn.tsx`의 `isLocked`는 `stage.name === '지원 전'`이며, 이 파일에 `getStageType` 호출이 없다
- AC-02 케밥 메뉴의 '이름 수정'·'삭제' 항목 `disabled`, `startEditing`의 return 조건, 단계명 `cursor-text` 조건은 모두 `isLocked`를 쓴다 (조건 구조는 기존과 같다)
- AC-03 컬럼 드래그 비활성 조건(`disabled: isDraft || stage.name === '지원 전'`)과 `KanbanBoard.tsx`·`stageAnalytics.ts`는 바뀌지 않는다. 변경 파일은 `KanbanColumn.tsx` 하나뿐이다
- AC-04 파일 상단 주석이 더 이상 "3개 기본 스테이지 모두 … 비활성화"라고 적지 않고, '지원 전'만 잠그는 이유와 '면접'·'최종 결과'를 허용하는 정책(HT-003)을 적는다
- AC-05 `npm run typecheck`·`npm run build`·`npm run lint`가 통과한다
- AC-06 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`의 `/kanban`에서 로그인 후 아래가 모두 맞다
  - '지원 전' 헤더의 더보기(···) 메뉴에서 '이름 수정'·'삭제'가 회색(비활성)이고, 단계명을 더블클릭해도 편집 모드가 되지 않는다. 컬럼을 드래그할 수 없다
  - '면접' 헤더의 더보기 메뉴에서 '이름 수정'을 누르면 편집 모드가 되고, 새 이름을 Enter로 저장하면 '전형 단계 이름이 수정되었어요.' 토스트와 함께 이름이 바뀐다. 단계명 더블클릭으로도 편집 모드가 된다
  - '최종 결과'(또는 이름을 바꾼 기본 단계)의 더보기 메뉴에서 '삭제'를 누르면 삭제 모달이 뜨고, 확인하면 단계가 사라진다 (카드가 있으면 기존 사용자 추가 단계와 같은 이동 흐름을 따른다)
  - 사용자 추가 단계의 이름 수정·삭제는 기존과 같다
