# HT-007 — 첨부 파일에 PNG·JPG 형식 추가와 첨부 가능 형식 사전 안내 (HT-007·HT-008)

## 배경

- 사용성 개선 리스트 `docs/heightening/Heightening_LIST.md`의 HT-007·HT-008 항목을 함께 처리한다. 리스트 비고에 "안내 문구에 PNG, JPG가 포함되므로 HT-007과 함께 처리한다"고 되어 있다
  - HT-007 TO-BE: 첨부 파일에 PNG, JPG 형태의 서류를 첨부할 수 있도록 한다 (전형 관련 캡처본·시각 자료 보관 수요)
  - HT-008 TO-BE: 첨부할 수 있는 파일 형식(PDF, DOCX, PPTX, PNG, JPG)을 업로드 이전부터 업로드 필드 아래쪽에 안내한다 (AS-IS `docs/heightening/images/HT-008-1.png`, `docs/heightening/images/HT-008-2.png`)
- 백엔드 답변 (2026-10-25): 업로드 가능한 확장자는 `pdf`, `docx`, `pptx`, `png`, `jpg`, `jpeg` 6개다. `.jpeg`는 `.jpg`와 같은 형식이라 함께 허용한다. 이 6개 외에는 모두 `UNSUPPORTED_FILE_TYPE` 예외가 발생한다. 업로드 API(`docs/API_SPEC.md` 4.1 `POST /api/v1/kanban/cards/{cardId}/documents/file`)의 요청·응답 형식은 바뀌지 않는다
- 지금 코드 (2026-10-25 develop `ad984b7` 기준)
  - `src/features/kanban/components/CardDetailDrawer.tsx`
    - `ALLOWED_FILE_EXTENSIONS = ['.pdf', '.docx', '.pptx']`, `validateFile`이 확장자가 맞지 않으면 `'PDF, DOCX, PPTX 파일만 첨부할 수 있어요.'`를 돌려준다. 파일 이름을 소문자로 바꿔 끝부분을 비교하므로 대문자 확장자도 통과한다
    - `handleFileSlotClick`의 파일 선택창 `input.accept = '.pdf,.docx,.pptx'`
    - '첨부 파일' 영역: 제목 → 업로드 슬롯 버튼('첨부할 파일을 추가해주세요.') → 첨부 목록(`fileItems`) → 에러 문구(`fileError`, `text-1 font-medium text-status-negative`) 순서다. 업로드 전에 형식을 알려주는 문구가 없다
  - `src/features/policy/data/terms-of-service.ts` 제13조에 "회원이 등록할 수 있는 첨부 파일은 PDF, DOCX, PPTX 형식이며 …"라고 적혀 있다
  - `docs/API_SPEC.md` 4.1 Request 표의 `file` 설명이 `PDF, DOCX, PPTX (최대 10MB)`다

## 범위

**포함**

- 파일 선택 단계의 허용 확장자에 `.png`, `.jpg`, `.jpeg`를 추가한다 (검증·파일 선택창 `accept`)
- 형식 오류 문구에 PNG, JPG를 넣는다
- 업로드 슬롯 버튼 바로 아래에 첨부 가능 형식과 최대 용량 안내 문구를 항상 보여준다
- 이용약관 제13조의 첨부 형식 문구와 `docs/API_SPEC.md` 4.1 Request 표의 형식 설명을 실제 허용 형식에 맞춘다

**제외**

- 파일 용량 제한(10MB), 계정 저장 용량(100MB), 저장 실패 시 에러 처리(`handleSave`의 `STORAGE_LIMIT_EXCEEDED` 분기 포함)는 바꾸지 않는다
- 첨부 목록 행(`src/features/documents/components/AttachedFileItem.tsx`)에 형식별 아이콘·이미지 미리보기를 넣지 않는다
- 이용약관의 시행일(`effectiveDate`)·부칙의 시행 문구·개정 이력은 바꾸지 않는다 (사용자 결정 2026-10-25: 문구만 수정, 정식 개정 절차는 PM과 따로 정한다)
- `docs/API_SPEC.md`의 상단 변경 이력(버전 노트)은 추가하지 않는다. 4.1 Request 표의 한 칸만 고친다
- `docs/heightening/Heightening_LIST.md`의 상태 갱신은 구현 PR에서 하지 않는다 (머지 후 일반 브랜치에서 처리)

## 설계 결정

- 허용 확장자는 백엔드 허용 목록과 같은 6개로 한다. 화면에 보이는 문구에는 `.jpeg`를 따로 적지 않고 "JPG"로 묶는다 (HT-007·HT-008 TO-BE의 표기를 따른다). 이용약관에는 법적 문서라 "JPG(JPEG)"로 적는다
- `src/features/kanban/components/CardDetailDrawer.tsx`
  - `ALLOWED_FILE_EXTENSIONS = ['.pdf', '.docx', '.pptx', '.png', '.jpg', '.jpeg']`
  - `validateFile`의 형식 오류 문구: `'PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요.'`
  - `input.accept`는 같은 6개 확장자를 쉼표로 이어 쓴다. 목록이 어긋나지 않게 `ALLOWED_FILE_EXTENSIONS.join(',')`로 만든다
  - 안내 문구: 업로드 슬롯 `<button>` 바로 다음, 첨부 목록(`fileItems.length > 0` 블록) 앞에 `<p className="text-1 font-medium text-label-description">PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요. (최대 10MB)</p>`를 둔다. 첨부 목록 유무·`fileError` 유무와 상관없이 항상 렌더링한다. 디자인 시안이 없어(디자이너 부재) 같은 화면의 보조 문구 크기(`text-1`)와 설명 색(`text-label-description`)을 쓴다
  - 기존 `fileError` 문구의 위치·스타일은 그대로 둔다
  - 안내 문구를 둔 이유(HT-008: 업로드 실패 뒤에야 형식을 알게 되는 문제)를 한국어 주석으로 짧게 남긴다
- `src/features/policy/data/terms-of-service.ts` 제13조 문장의 `PDF, DOCX, PPTX 형식이며`를 `PDF, DOCX, PPTX, PNG, JPG(JPEG) 형식이며`로 바꾼다. 문장의 나머지는 그대로 둔다
- `docs/API_SPEC.md` 4.1 Request 표의 `file` 설명을 `PDF, DOCX, PPTX, PNG, JPG, JPEG (최대 10MB)`로 바꾼다. 표의 다른 칸·열 너비 외의 내용은 바꾸지 않는다
- BE 의존: 없음 (백엔드 허용 확장자 반영 완료, 2026-10-25 답변)

## 수용 기준

- AC-01 `CardDetailDrawer.tsx`의 `ALLOWED_FILE_EXTENSIONS`가 `.pdf`, `.docx`, `.pptx`, `.png`, `.jpg`, `.jpeg` 6개이고, `validateFile`은 이 목록과 소문자 파일명 끝부분 비교로 형식을 검사한다
- AC-02 `validateFile`의 형식 오류 문구가 `'PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요.'`이고, 이 파일에 `'.pdf,.docx,.pptx'` 문자열이 남아 있지 않으며, `input.accept`는 `ALLOWED_FILE_EXTENSIONS.join(',')`로 정해진다
- AC-03 업로드 슬롯 버튼 바로 다음 형제 요소로 `text-1 font-medium text-label-description` 클래스의 `PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요. (최대 10MB)` 문구가 조건 없이 렌더링되고, 첨부 목록과 `fileError` 문구는 그 아래에 기존 순서대로 있다
- AC-04 `terms-of-service.ts` 제13조 문장이 `PDF, DOCX, PPTX, PNG, JPG(JPEG) 형식이며`를 포함하고, `effectiveDate`와 부칙(시행 문구·개정 이력)은 바뀌지 않는다
- AC-05 `docs/API_SPEC.md` 4.1 Request 표의 `file` 설명이 `PDF, DOCX, PPTX, PNG, JPG, JPEG (최대 10MB)`다
- AC-06 변경 파일은 `src/features/kanban/components/CardDetailDrawer.tsx`, `src/features/policy/data/terms-of-service.ts`, `docs/API_SPEC.md` 3개뿐이다
- AC-07 `npm run typecheck`·`npm run build`·`npm run lint`가 통과한다
- AC-08 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`의 `/kanban`에서 로그인 후 카드를 눌러 상세 드로어를 열면 아래가 모두 맞다
  - '첨부 파일' 업로드 슬롯 바로 아래에 `PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요. (최대 10MB)` 문구가 파일을 고르기 전부터 보인다
  - 슬롯을 눌러 열린 파일 선택창에서 PNG·JPG(JPEG) 파일을 고를 수 있고, 고른 파일이 첨부 목록에 쌓인다
  - PNG 1개와 JPG(또는 JPEG) 1개를 첨부하고 '저장'을 누르면 '저장되었어요.' 토스트가 뜨고, 드로어를 다시 열었을 때 두 파일이 목록에 있다. 파일 행을 누르면 다운로드된다
  - 지원하지 않는 형식(예: `.txt`)을 고르면 `PDF, DOCX, PPTX, PNG, JPG 파일만 첨부할 수 있어요.` 에러 문구가 보이고 목록에 추가되지 않는다 (파일 선택창의 형식 필터를 '모든 파일'로 바꿔 고른다)
  - 기존 PDF·DOCX·PPTX 첨부·저장은 기존과 같다
- AC-09 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`의 `/terms` 제13조에 `PDF, DOCX, PPTX, PNG, JPG(JPEG) 형식이며`가 보이고, 문서 상단의 시행일은 `2026.08.31` 그대로다
