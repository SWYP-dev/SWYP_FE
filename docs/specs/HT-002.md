# HT-002 — 지원 현황 카드 드래그앤드롭 시각적 피드백 추가

## 배경

- 사용성 개선 리스트 `docs/heightening/Heightening_LIST.md`의 HT-002 항목이다. 사용성 테스트에서 "카드가 실제로 움직이고 있는지, 어디에 놓이는지 알 수 없어 같은 동작을 여러 번 반복한다"는 문제가 나왔다 (AS-IS `docs/heightening/images/HT-002-1.png`)
- TO-BE는 "전형 단계(컬럼) 이동과 동일한 시각적 피드백"이다 (참고 `docs/heightening/images/HT-002-2.png`: 놓일 컬럼 배경이 연보라로 강조되고, 끌고 있는 컬럼의 원래 자리는 반투명으로 남는다)
- 지금 코드 (2026-10-22 develop `f1b0388` 기준)
  - 컬럼 드래그: `src/features/kanban/components/KanbanColumn.tsx`에서 끌고 있는 컬럼은 `opacity: isStageDragging ? 0.5 : 1`, 컬럼 배경은 `useDroppable`의 `isOver`가 true일 때 `bg-fill-primary-light`, 아니면 `bg-surface-card`
  - 카드 드래그: `src/features/kanban/components/KanbanCard.tsx`에서 끌고 있는 카드의 원래 자리는 `opacity: isDragging ? 0 : 1`로 완전히 숨긴다. 커서를 따라가는 카드는 `KanbanBoard.tsx`의 `DragOverlay`가 그린다
  - `KanbanBoard.tsx`의 `handleDragOver`는 카드가 다른 컬럼 위로 가면 로컬 상태에서 카드를 그 컬럼으로 미리 옮긴다. 그런데 옮겨진 카드도 `opacity: 0`이라 놓일 자리가 빈칸으로만 보인다
  - 카드 드래그 중에는 충돌 대상(`over`)이 대부분 카드(`useSortable`)라서, 컬럼의 `useDroppable` `isOver`가 거의 true가 되지 않는다. 그래서 놓일 컬럼 강조도 사실상 보이지 않는다

## 범위

**포함**

- 카드를 드래그하는 동안, 카드가 놓일 컬럼의 배경을 컬럼 드래그와 같은 `bg-fill-primary-light`로 강조한다
- 끌고 있는 카드의 자리(원래 컬럼 또는 `handleDragOver`로 옮겨진 컬럼)를 숨기지 않고 컬럼 드래그와 같은 반투명(0.5)으로 보여준다

**제외**

- 컬럼(전형 단계) 드래그의 기존 피드백은 바꾸지 않는다
- 카드 이동 API 호출·순서 계산·실패 시 롤백 등 드래그 로직(`handleDragEnd`의 `moveCardMutation` 흐름)은 바꾸지 않는다
- `DragOverlay`로 그리는 카드의 모양(그림자·크기 등)은 바꾸지 않는다
- `docs/heightening/Heightening_LIST.md`의 상태 갱신은 구현 PR에서 하지 않는다 (머지 후 일반 브랜치에서 처리)

## 설계 결정

- 디자인 시안이 없으므로 새 색·값을 만들지 않고, 컬럼 드래그에서 이미 쓰는 값(`bg-fill-primary-light`, opacity `0.5`)을 그대로 쓴다
- `src/features/kanban/components/KanbanBoard.tsx`
  - 카드가 현재 위에 있는 컬럼 ID를 담는 state `dragOverStageId: number | null`(초기값 `null`)을 추가한다
  - `handleDragOver`에서 끌고 있는 것이 카드(`active.data.current?.type === 'card'`)이면, 기존의 "같은 컬럼이면 return" 조건보다 **먼저** `over.data.current?.stageId`(없으면 `null`)로 갱신한다. `over`가 없으면 `null`로 갱신한다. 같은 컬럼 안에서 순서만 바꿀 때도 그 컬럼이 강조되어야 하기 때문이다
  - `handleDragEnd`와 `onDragCancel`에서 `activeDragCard`를 비우는 곳에서 `dragOverStageId`도 `null`로 되돌린다
  - 각 `KanbanColumn`에 `isCardDropTarget={activeDragCard !== null && dragOverStageId === stage.id}`를 넘긴다. draft 컬럼에는 넘기지 않는다
- `src/features/kanban/components/KanbanColumn.tsx`
  - 선택 prop `isCardDropTarget?: boolean`(기본값 `false`)을 추가한다
  - 컬럼 배경 조건을 `isOver || isCardDropTarget`일 때 `bg-fill-primary-light`, 아니면 `bg-surface-card`로 바꾼다. 나머지 클래스는 그대로 둔다
- `src/features/kanban/components/KanbanCard.tsx`
  - `KanbanCard`의 style을 `opacity: isDragging ? 0.5 : 1`로 바꾸고, 바로 위 주석을 "놓일 자리를 보여주기 위해 반투명으로 남긴다(HT-002)"는 취지로 고친다
- 바꾼 부분에는 왜 바꿨는지 한국어 주석을 짧게 남긴다 (`.claude/rules/code-style.md`)
- BE 의존: 없음

## 수용 기준

- AC-01 `src/features/kanban/components/KanbanCard.tsx`의 `KanbanCard`가 드래그 중(`isDragging`)일 때 opacity `0.5`를 쓰고, `isDragging ? 0 :` 표현이 남아 있지 않다
- AC-02 `src/features/kanban/components/KanbanBoard.tsx`에 `dragOverStageId` state가 있고, `handleDragOver`에서 카드 드래그일 때 같은 컬럼 여부 검사보다 먼저 갱신되며, `handleDragEnd`·`onDragCancel`에서 `null`로 초기화된다
- AC-03 `src/features/kanban/components/KanbanColumn.tsx`에 선택 prop `isCardDropTarget`이 있고, 컬럼 배경이 `isOver || isCardDropTarget`일 때 `bg-fill-primary-light`다. `KanbanBoard.tsx`는 일반 컬럼에 `isCardDropTarget={activeDragCard !== null && dragOverStageId === stage.id}`를 넘긴다
- AC-04 변경 파일은 `KanbanBoard.tsx`·`KanbanColumn.tsx`·`KanbanCard.tsx` 3개뿐이고, `handleDragEnd`의 카드 이동 API 호출·롤백 코드는 바뀌지 않는다
- AC-05 `npm run typecheck`·`npm run build`·`npm run lint`가 통과한다
- AC-06 [manual] Vercel 프리뷰 또는 로컬 `npm run dev`의 `/kanban`에서 로그인 후 아래가 보인다
  - 카드를 다른 컬럼으로 끌면, 커서가 올라간 컬럼의 배경이 연보라(`bg-fill-primary-light`)로 바뀌고 그 컬럼 안에 카드가 놓일 자리가 반투명 카드로 보인다
  - 같은 컬럼 안에서 순서를 바꿀 때도 그 컬럼이 강조되고, 반투명 카드가 들어갈 위치로 움직인다
  - 카드를 놓으면 강조와 반투명이 사라지고, 카드가 놓인 컬럼·순서가 새로고침 후에도 유지된다
  - 컬럼(전형 단계)을 끌 때의 피드백은 기존과 같다
