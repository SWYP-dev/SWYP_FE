# 사용성 개선(Heightening) 리스트

최종 갱신일: 2026-10-22 (HT-001~HT-009 등록, 디자인 결정 기준·처리 순서 추가)

사용성 테스트에서 나온 문제를 바탕으로 한 개선 작업을 기록한다. 버그·명세 불일치를 다루는 QA(`docs/qa/QA_LIST.md`)와 달리, 동작은 하지만 사용하기 불편한 지점을 개선하는 작업이다.

## 사용법

- **ID**: `HT-001`부터 순서대로 붙인다.
- **우선순위**: 두지 않는다. 처리 순서는 별도로 정한다.
- **처리 순서**: 백엔드 선행이 필요한 HT-007·HT-008은 가장 마지막에 처리한다. 나머지는 등록 순서대로 진행한다.
- **디자인 결정 기준**: 디자이너가 부재한 상태다(2026-10-22 기준). Figma 시안이 없는 디자인 변경은 가장 보편적으로 쓰이는 UI 형태를 기준으로 정해서 적용하고, 정한 값은 항목의 "비고"에 기록한다. 판단이 애매하거나 레퍼런스가 필요한 항목은 적용 전에 레퍼런스를 요청한다.
- **상태**: `대기` / `진행중` / `완료` 3단계로 관리한다.
- **참고 이미지**: 항목에 첨부할 이미지는 `docs/heightening/images/` 아래에 `HT-001-1.png`처럼 항목 ID를 붙인 파일명으로 저장하고, 항목의 "참고 이미지" 필드에 상대경로로 기록한다.

## 개선 항목

#### [HT-001] 지원 현황에 추가한 공고의 버튼을 '지원 완료'로 변경

- 기능명: 통합 공고 목록 조회
- 상태: 완료
- 사용성 문제: 지원 완료한 공고의 인식이 어려움
- 개선 사항: 지원 완료 공고의 버튼 이름 변경
- 상세 내용:
  - AS-IS: 지원 현황에 추가한 공고도 '지원 현황 추가' 버튼이 그대로 활성화되어 있어서, 지원을 완료한 공고인지 인식하기 어렵다.
  - 근거: 이미 추가한 공고인지 구분이 안 되어 중복으로 클릭하거나 상태 파악에 혼선이 생긴다.
  - TO-BE: 지원 현황에 추가를 완료한 공고는 '지원 현황 추가' 버튼이 '지원 완료'로 바뀌고 버튼이 비활성화된다.
- 참고 이미지: [images/HT-001-1.png](images/HT-001-1.png)(AS-IS 공고 카드 버튼)
- 비고: **백엔드 요청 필요** (2026-10-22). 공고 목록 API(`GET /api/v1/feed`)의 `FeedItem`에 칸반 등록 여부 필드가 없음(명세·실제 응답 모두 확인). 공고 상세(2.2)·스크랩 목록(2.5)에는 `isKanbanRegistered`가 있으므로 피드 목록에도 같은 필드 추가를 요청한다.
  - 임시 처리(공고 탐색): 이 화면에서 추가에 성공했거나 '이미 등록됨'(K003) 응답을 받은 공고만 '지원 완료'로 바꾼다. 새로고침하면 초기화된다. 필드가 추가되면 응답값으로 교체한다.
  - 스크랩 페이지: 같은 공고 카드를 쓰므로 함께 적용. 스크랩 목록 API의 `isKanbanRegistered` 값을 그대로 쓴다.
  - 디자인: 시안이 없어 기존 비활성 outline 버튼('원본 링크 없음'과 같은 스타일)을 그대로 쓴다.
  - 완료 처리(2026-10-22): 로컬 dev 서버에서 공고 탐색·스크랩 화면 동작 확인. 백엔드 필드가 추가되면 공고 탐색의 임시 처리를 응답값으로 교체하는 후속 작업이 남아 있다.

#### [HT-002] 지원 현황 카드 드래그앤드롭 시각적 피드백 추가

- 상태: 완료

- 상세 내용:
  - AS-IS: 카드를 드래그할 때 카드만 따라 움직이고, 놓일 위치에 대한 표시가 없다.

  - TO-BE: 공고 카드 드래그앤드롭 시 시각적 피드백을 제공한다 (전형 단계 이동 시의 피드백과 동일하게).

#### [HT-004] 전형 단계 추가 후 단계명 작성 도중 취소 기능 제공

- 기능명: 지원 현황 단계
- 상태: 완료
- 사용성 문제: 지원 현황 단계 추가 후 단계명 작성 도중 단계 삭제가 불가
- 개선 사항: 추가한 전형명 편집 중 단계 삭제 기능 제공
- 상세 내용:
  - AS-IS: 오기입했거나 불필요해진 전형을 작성 도중에 바로 취소/삭제할 수 없어 조작이 불편하다.
  - 근거: 유저가 실수로 단계를 추가했을 때 취소할 방법이 없어, 아무 이름이나 입력한 뒤 삭제하는 우회 행동을 해야 한다. → 사용성이 떨어짐
  - TO-BE:
    - Enter: 이름이 유효하면 저장
    - ESC: 입력 취소, 단계 자체가 사라짐
    - 바깥 클릭: 이름이 있으면 저장, 비어 있으면 그냥 사라짐
    - 이름이 형식에 맞지 않을 때: 에러 문구는 보여주되, 취소는 언제든 가능해야 함
- 참고 이미지: [images/HT-004-1.png](images/HT-004-1.png)(AS-IS 빈 값 에러 상태)
- 비고: QA-006(빈 값 상태에서 바깥 클릭 시 자동 취소, `완료`)과 겹치는 부분이 있음. 작업 시 TO-BE 4가지 동작을 현재 동작과 하나씩 비교해, 이미 동작하는 것과 남은 범위(ESC 취소, 에러 상태에서의 취소 등)를 나눠서 처리한다. 비교 결과 Enter 저장·ESC 취소·바깥 클릭은 이미 동작했고, 형식 오류 상태에서의 취소만 남아 있었다. 추가 중인 단계 헤더에 닫기(X) 버튼을 두는 것으로 명세 `docs/specs/HT-004.md`(spec PR #214) → Codex 구현 PR #215 머지로 완료(2026-10-22).

#### [HT-005] 마감 임박 공고 D-day 강조색 변경

- 기능명: 지원 마감일 목록 조회
- 상태: 완료
- 사용성 문제: 마감 임박 공고가 눈에 띄지 않음
- 개선 사항: 마감 임박 공고 D-day 강조
- 상세 내용:
  - AS-IS:
    - 현재의 강조색(파란색)으로는 강조가 약하다.
    - 마감 임박 공고처럼 중요도가 높은 항목에는 확실한 시각적 강조가 필요하다.
  - TO-BE: 강조색을 확실한 시각적 강조를 줄 수 있는 다른 색상으로 변경한다.
- 참고 이미지: [images/HT-005-1.png](images/HT-005-1.png)(AS-IS 오늘 D-Day 영역)
- 비고: "디자인 결정 기준"에 따라 마감 임박 표시에 보편적으로 쓰이는 빨간색으로 결정. 기존 토큰 `status-negative`(#fb322e)를 사용해 오늘·내일 그룹 헤더 텍스트(`text-status-negative`)와 카드 왼쪽 Divider(`bg-status-negative`)를 변경. 강조 대상(오늘·내일)은 그대로.
  - 기존 조건(`diffDays <= 1`)에 마감 지난 그룹(D+N)도 섞여 같이 강조되던 것을 분리해, 지난 마감은 회색(헤더 `text-label-description`, Divider `bg-neutral-400`)으로 표시(사용자 요청, 2026-10-22).
  - 완료 처리(2026-10-22): 로컬 dev 서버의 `/deadlines`에서 화면 확인.
