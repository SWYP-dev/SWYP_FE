## **1. 제품 개요**

### **1.1 서비스 한 줄 정의**

> 취업 공고 탐색부터 지원 서류, 전형 진행 상태까지 한 곳에서 통합 관리하는 취업 준비 서비스

### **1.2 핵심 가치 제안**

| **기존 문제**                                       | **취합이 제공하는 해결**                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 지원한 공고가 많아질수록 진행 상태 파악이 어렵다.   | 칸반 보드 형태로 지원 현황과 전형 단계를 한눈에 파악하고 직관적으로 관리할 수 있도록 한다. |
| 기업마다 제출한 서류를 찾기 어렵다.                 | 지원한 공고별로 서류를 연동해, 흩어진 서류들을 한 곳에서 관리한다.                         |
| 여러 사이트를 오가며 공고를 찾아야 한다.            | 여러 플랫폼의 공고를 한 곳에서 탐색하고 스크랩한다.                                        |
| 공고별 일정을 캘린더에 수동 입력해야 한다.          | 공고 등록 시 서비스 내 캘린더에 일정을 자동 등록한다. (v1.7)                               |
| 수많은 공고들로 인해 일정을 놓치는 경우가 발생한다. | 서비스 내 캘린더 일정을 바탕으로 카카오톡 리마인드를 제공한다. (v1.7)                      |
| 맞는 공고를 찾느라 시간을 낭비한다.                 | 온보딩 AI 분석 기반의 맞춤 공고를 추천한다. (v1.7)                                         |

### **1.3 핵심 용어 정리**

- **단계 (전형 단계):** 칸반 보드의 세로 열을 의미하며, 유저가 편집 및 순서 변경이 가능한 단위
  (Ex. 지원 전, 면접, 최종 결과)
- **카드 (공고 카드):** 통합 공고 피드 및 칸반 보드의 각 단계 내부에 들어가는 개별 공고 데이터
- **상세 패널:** 공고 카드를 클릭했을 때 화면 전환 없이 우측에서 슬라이드로 열리는 창으로, 공고의 상세 정보 조회, 칸반 보드 등록, 원본 공고로의 이동이 이루어지는 공간
- **통합 공고 피드:** 여러 채용 플랫폼에서 수집한 전체 공고들이 있는 화면
- **지원 마감일:** 채용 플랫폼에서 수집하거나 유저가 입력하는 공고의 접수 종료일로, 캘린더 자동 등록 및 리마인드 알림의 기준이 되는 데이터 (= 서류 마감일)

#### **공고 사전 저장(캐싱) 규칙:**

- **수집 주기:** 일 2회(8:00, 20:00 / 채용 공고 특성상 실시간 갱신 불필요)
- **저장 방식:** API 호출 제한 및 약관 대응을 위해 실시간 호출 대신 내부 저장소(Redis/DB)의 캐시 데이터를 노출
- **피드 데이터 만료:** 지원 마감일이 지난 공고는 '통합 공고 탐색'에서 자동 제외

### **4.1.4 스크랩**

- **정의:** 통합 공고 탐색 피드에서 찾은 관심 공고를 개인 공간에 스크랩하고, 칸반 보드에 바로 등록할 수 있는 탭이다.
- **목적:** 관심 공고가 휘발되는 것을 방지하고, 공고 탐색부터 지원 관리까지의 과정을 매끄럽게 이어주어 유저의 채용 후보군을 체계적으로 관리할 수 있도록 한다.

### 4.3 **⭐ 마감 일정 관리** (Phase 3 / MVP)

### 4.3.1 지원 마감일

- **개요:** 칸반 보드에 등록된 공고들의 마감일과 주요 공고 정보를 한눈에 파악할 수 있는 목록 뷰 제공
- **노출 대상:** 칸반 보드에 등록된 공고 전체
- **노출 정보:** 공고 식별에 필요한 핵심 정보 일괄 노출 (기업명, 공고명, 지원 마감일, 전형 단계)
- **상세 정보:** 각 공고 클릭 시 드로어 형태로 공고 상세 정보 노출
  (기업명, 공고명, 직무 분류, 지원 마감일, 지역, 경력, 원본 공고로 이동 버튼, 메모, 서류)
- **정렬 옵션:** 마감일 임박순 자동 정렬
- **편집 항목:** 지원 마감일, 전형 단계 수정 가능 [v1.6.0 추가]

### 4.3.2 알림 기능

- **목적**
  - 유저의 주요 채용 일정(지원 마감일 등)을 적시에 통지하여 채용 기회 누락을 방지함
- **구현 범위**
  - **웹페이지 내부 알림창**과 **이메일 알림**으로 병행하여, 유저의 주요 채용 일정을 상시 인지할 수 있도록 함
    - **웹페이지 내부 알림창** [v1.6.0 추가]
      - **기본 조회:** 최신 알림 목록 10개 단위 노출
      - **추가 조회:** '더보기' 버튼 클릭 시 알림 10개씩 추가 노출
      - 생성일 기준 90일 경과 시 자동 삭제
      - 개별 삭제 및 일괄 삭제 기능 제공
    - **이메일 알림** [v1.6.0 추가]
      - 설정 페이지에서 수신 여부 설정 가능

### **4.5 ⭐캘린더 자동 등록 (Phase 5 / v1.7.0)**

<aside>

💡MVP 출시 범위에서는 제외하되, 개발 일정의 여유가 확보될 경우 도입을 검토하는 차기 개발 후보 기능입니다.

</aside>

### 4.5.1 기능 정의 및 비즈니스 목적

<aside>

- **정의:** 칸반 보드 등록 시 지원 마감일을 자동으로 인식하여 서비스 내 캘린더에 등록 및 시각화하는 기능
- **목적:** 클릭 한 번으로 지원 마감일을 자동 등록하여 유저가 중요한 채용 기회를 놓치지 않도록 방지
- **비고:** 서류 전형 이후 개별 안내받은 면접일 등은 유저가 직접 수동으로 입력·보완하도록 지원

</aside>

### 4.5.2 캘린더 자동 등록 및 화면 동작 규칙

| **항목**       | **세부 동작 규칙**       |
| -------------- | ------------------------ |
| 일정 생성 조건 | • **서류 마감일 (자동)** |

      ◦ `[내 캘린더에 등록]` 클릭 시 지원 마감일 데이터를 자동 추출
      ◦ 캘린더에 "{기업명} 지원 마감" 일정 생성

### **4.7 ⭐온보딩 AI 맞춤 공고 추천 (Phase 7 / v1.7.0)**

<aside>

💡MVP 출시 범위에서는 제외하되, 개발 일정의 여유가 확보될 경우 도입을 검토하는 차기 개발 후보 기능입니다.

</aside>

### 4.7.1 기능 정의 및 비즈니스 목적

<aside>

- **정의:** 유저가 입력한 온보딩 정보를 기반으로 AI가 개인 맞춤형 채용 공고를 제공하는 기능
- **목적:** 수많은 공고 속에서 유저에게 딱 맞는 공고를 빠르고 정확하게 제안하여 탐색 비용을 줄이기 위함
- **비고:** 외부 LLM API(Claude, ChatGPT 등)에 유저 온보딩 데이터와 공고 목록 데이터를 전달하여 추천 결과를 받아오는 방식을 우선적으로 검토함

</aside>

### 4.7.2 온보딩 정보 수집 항목

- **직무 분야:** 다중 선택형 (예: 개발, 디자인, 마케팅 등)
- **경력 구분:** 선택형 (신입 / 경력 N년 등)
- **희망 기업 규모:** 다중 선택형 (스타트업, 중견기업, 대기업 등)
- **희망 연봉 범위:** 범위 선택형
- **선호 근무 형태:** 다중 선택형 (재택/오피스/하이브리드 등)

### 4.7.3 AI 추천 시스템 동작 규칙

- **추천 결과 노출**
  - 온보딩 단계 작성 완료 시, AI 맞춤 추천 공고 리스트를 확인할 수 있도록 화면 구성
  - AI 매칭률이 높은 상위 5~20개만 임팩트 있게 노출 (비용 및 속도 최적화)

### 4.7.4 기술적 의존성 및 제약 사항

- **AI 추천 데이터 갱신 및 캐싱 정책**
  - **자동 갱신 (주기적)**
    - **동작 규칙:** 신규 공고 발생 시 반영하되, 최소 N시간 단위로 캐싱 데이터 자동 만료 및 재호출 수행
    - **목적:** 과도한 API 호출 방지 및 시스템 부하 최적화
  - **즉시 갱신 (온보딩 변경 시)**
    - **동작 규칙:** 유저의 온보딩 정보 변경 이벤트 발생 즉시, 기존 캐싱 주기와 무관하게 AI API 호출 및 데이터 갱신
    - **목적:** 사용자 설정값 즉각 반영 및 추천 정확도 보장

## **5. 기능 간 연동 규칙**

### 5.1 칸반 보드에서 공고 카드를 삭제하는 경우

- **스크랩 상태:** 공고 카드를 삭제하더라도 스크랩 목록에는 유지한다.
  (추후 칸반 카드 삭제 시 "스크랩도 함께 해제하시겠어요?" 제공 검토)
- **첨부된 서류:**
  공고 카드 삭제 시 해당 카드에 첨부된 파일, 외부 링크, 메모 데이터는 함께 삭제되며 복구할 수 없다.
  (추후 공고 카드 삭제 시 "공고 카드를 삭제하시겠어요? 첨부된 서류 파일 및 메모 데이터도 함께 삭제되며 복구할 수 없어요.” 등 제공 검토)
- **지원 마감일 목록:** 공고 카드 삭제 시 지원 마감일 목록에서도 해당 공고를 자동 제거한다.

### 5.2 스크랩을 해제하는 경우

- **이미 지원 현황에 등록된 경우:** 지원 현황(칸반)의 공고 카드는 유지 후 스크랩 목록에서만 제거된다.

### 5.3 원본 공고가 마감/삭제된 경우

- **통합 공고 피드:** 피드에서 즉시 제외
- **스크랩:** 유지하되, 회색으로 처리되며 "마감되었거나 삭제된 공고예요." 표시
- **지원 현황 관리:** 유지하되, 회색으로 처리되며 "마감되었거나 삭제된 공고예요." 표시

### 5.4 단계 이름을 변경한 경우

- 지원 마감일 목록에 표시되는 단계명에도 즉시 반영된다.

### 5.5 API 공고 정보가 변경된 경우

- 기업명, 공고명, 지원 마감일 등은 최신 정보로 갱신한다.
- 사용자가 작성한 메모 및 첨부 파일은 유지한다.
